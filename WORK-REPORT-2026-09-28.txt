1. VIDEO-CALL ROOT-CAUSE DEBUG + FIX (main task)
------------------------------------------------
Problem : caller stuck on "Connecting..." forever; cancelling logged a
false "Missed Video Call". Instruction: fix root cause, not UI.

ROOT CAUSE #1 (definitive, code-proven): RtcWebSocket.onMessage had NO
branch for incoming ICE candidates. Both sides SENT candidates
(onIceCandidate -> sendCandidate worked) but every received candidate frame
was silently dropped (parser `when` fell through to Unit). Without remote
candidates ICE can only succeed via same-LAN host candidates; across
NAT/mobile data the PeerConnection sits in CHECKING forever -> infinite
"Connecting...".

ROOT CAUSE #2 (definitive): CallViewModel.endCall logged MISSED for
INCOMING *or* CONNECTING regardless of direction, so a caller cancelling
while connecting got a false MISSED entry.

ROOT CAUSE #3 (robustness): no connection watchdog, no offer retry (offer
sent once on socket open; callee joining late never gets it), duplicate
socket-Connected re-fires offer, socket drop killed even CONNECTED calls.

ROOT CAUSE #4 (permissions): no CAMERA/RECORD_AUDIO runtime request anywhere
in the call flow; fresh installs deny by default -> startCapture throws.
