10. EMULATOR DISCONNECT / "OFFLINE" FIX (evening update)
================================================================
Symptom: 172.16.70.42:5555 dropped suddenly all day; reconnects
          reported `offline` / `not found`; bulk pushes died at random
          byte counts; pm/settings/svc binder calls hung while `echo`
          still worked.
Root cause (two compounding issues, both proven live):
1. TWO adb servers fighting: SDK platform-tools adb (v37.0.1,
   PID 2816) + scrcpy-bundled adb (v37.0.0, PID 17028), plus a third
   copy under Downloads/platform-tools. Version-mismatched servers
   kill each other on startup and drop the device mid-task.
2. Emulator system services wedging over uptime (same disease as the
   morning pm stall): binder calls into system_server blocked while
   trivial shell still answered.
Fix applied + verified:
- Both servers killed (graceful `kill-server`); ONE server now: SDK
  adb (PID 8700, v37.0.1).
- User env ADB set to the SDK adb so scrcpy uses the same binary
  (takes effect in fresh terminals) - ends the server wars.
- `adb reboot`: pm/settings/svc instantly responsive again.
- Device anti-sleep stored: stay_on_while_plugged_in=3,
  wifi_sleep_policy=2 (both read back OK).
- NOTE: `adb reconnect` once dropped the device instead of reviving
  it (recovered via disconnect/connect); prefer the ladder below.
Recovery ladder (in order): `adb reconnect` (check devices after) ->
`adb disconnect` + `adb connect` -> graceful `adb kill-server`
(never force-kill; any adb command restarts one clean server) ->
`adb reboot` (sure fix for hanging binder calls).
Caveat: WiFi link still ~0.1 MB/s at peak hours - disconnects are
fixed, 70 MB deploys still take ~10+ min (USB ADB recommended).
